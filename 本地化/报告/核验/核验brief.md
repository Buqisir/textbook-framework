## 任务
你负责的讲义见派活消息。对每一册，**以第一次拿到这本讲义的学生和老师的身份，从头到尾读一遍**。
读 PDF：`pdftotext -layout 渲染/本地化/_out/<名>.pdf -`。版式问题需要看图时，用 `pdftoppm -r 60 -f N -l N -png` 出页图，再用 Read 看。

带着三个问题读：
1. **疑惑**：哪些解析、知识的排列会让学生或老师看不懂、产生疑问？例如：
   - 讲解没说清为什么；
   - 例题与讲解块对不上；
   - 归类理由缺失；
   - 术语前后不一；
   - 答案和解析矛盾；
   - 题目放在了不相干的专题或考法下。
2. **不友好**：哪些地方读起来、用起来不顺？例如：
   - 编辑说明腔、AI 腔（见 05 一.1–一.3 的禁用词）；
   - 散报数据；
   - 提示过长；
   - 题号或答案对不上；
   - 题干有残缺或乱码、多余空位；
   - 答案页难找、难对。
3. **错误**：讲解或知识性错误，例如：
   - 语法规则讲错；
   - 例句或答案错；
   - 词性转换链里的词形、词性、拼写错；
   - 单元中文名错（对照人教版 2019 新教材单元标题）；
   - 短语标题与原题实考搭配不一致。

## 修正规则
- **只改定稿 JSON**（`本地化/内容/段考-*.定稿.json` / `同步-*.定稿.json`）。不改 CSS、不改脚本、不改语料、不改题库。
  - 如果确实需要改脚本、语料或 CSS，写进报告的「需负责人处理」一节。
- 原题不改。题库答案有错时，用 `answer_show` 印改正写法，reason 说明改了什么（见 05 三.3）。
- 不编题，不加统计，不写编辑说明。写法照 05。
- 拿不准的知识点不要改，写进报告请负责人裁决。
- 改完逐册执行：
  ```bash
  python3 -I 本地化/脚本/定稿校验.py          # 必须「问题：无」
  python3 -I 本地化/脚本/段考排版.py <年级学期> <节点>   # 或 同步排版.py <册>
  cd 渲染/本地化 && ../node_modules/.bin/vivliostyle build <名>.html -o _out/<名>.pdf --timeout 180 --executable-browser /opt/pw-browsers/chromium-1243/chrome-linux64/chrome; cd ../..
  python3 -I 调研/视觉重做/工具/指标.py 渲染/本地化/_out/<名>.pdf   # 半格对齐率 100%，英文最长行 ≤ 80
  python3 -I 本地化/脚本/孤标题检查.py 渲染/本地化/_out/<名>.pdf
  ```
- **不要 git commit、不要 push**：多个 agent 共用一个工作区，由负责人统一提交。
  - 只动你负责的那几册定稿。
  - 定稿校验.py 会同时校验所有册。别的册报错与你无关时，在报告里注明即可。
