# 通读修改 brief（2026-11-06）

## 背景

23 册讲义通读后，负责人核实出待改清单：`本地化/报告/通读/清单.md`。你负责其中**分给你那几册的内容层条目**（第二、三节）。第一节（脚本、版式）由负责人改，你不碰。

接手前先读：`规范/05-所有者修改原则.md`；段考读 `本地化/内容/段考-写作要求.md`，同步读 `本地化/内容/同步-定稿模板.md`。

## 规矩

- **只改分给你的定稿**：`本地化/内容/<册>.定稿.json`。不改脚本、CSS、HTML、候选、题库、`数据/题干修订.tsv`，不提交 git。
- 写回 JSON 时**保留原缩进**：先看原文件用几格缩进，用 `json.dump(d, f, ensure_ascii=False, indent=<原缩进>)`，末尾换行与原文件一致。改完 `git diff --stat` 看一眼，只该有你那几个文件、改动行数合理。
- **题干的病句、错字不归你**（另一组登记进 `数据/题干修订.tsv` 统一执行）。你只改讲解、例题解析、要点、答案（ans / why / answer_show）这些。讲解、解析里的中文错字（如「过去完成时时」「同义句转化」→「转换」「→ =」）归你。
- 只用东莞原题，不编题。措辞用编辑口吻，短；不用「先看……再……」「抓住/记住/其实/关键是」、破折号；不写编辑说明（「不单列」「本册不讲」「同上」「题库」等）。
- 答案多解用「/」，可省部分用括号。练一练 why 不超过 20 字。

## 一、讲解例句就是练一练原句（段考，清单二.1，量最大）

问题：讲解框（explain 的 p / pattern / note）或要点（keypoint）里举的例子，正好是本册练一练某题的原句或带答案的片段，学生读完讲解就能抄答案。

1. 初筛清单在 `本地化/报告/通读/泄题.md`（脚本按「答案 + 题干前后一词」做子串比对）。找你那几册的行。
2. **逐条判断**：
   - 讲解里确实引用了这道题的句子或带答案的片段（如「如 Compared with、Burying himself」而练一练有 ___ (bury) himself…）→ 要改。
   - 命中的只是规则本身要讲的结构词（如讲解 pattern 写 appreciate it if、consider it necessary、only to find，练一练恰好考它）→ 不是泄题，不改，在结果里记「误报」。判断标准：把讲解里这处换成别的词，规则还讲得通吗？讲不通的是结构本身，不改。
3. 脚本会漏：答案只有一两个词、或讲解改写过句子的。**把你那几册每个专题的练一练答案和讲解、要点对一遍**，同样处理。
4. **改法：练一练不动，改讲解。** 讲解里的例子换成：本专题例题（examples）的句子或片段；或同册 `段考-<年级学期>-<节点>.候选.json` 里同专题、本册没印出的原题句子（核对题号不在本册其他位置）。去掉例子规则仍清楚的，也可以直接删掉例子。不要自己造英文例句。
5. 改完跑 `python3 -I 本地化/脚本/泄题检查.py 本地化/内容 <册名片段>`，剩下的行应该都是你判过的误报。

## 二、清单里的其他条目

清单第二节 2–7 和第三节「答案错」「答案应列出多种写法」「讲错」里，凡是写了你那几册名字的条目，逐条改。定位写法：「答 N」= 答案区第 N 题 = 全册练一练第 N 题；「练 N」同；「例 N」= 例题。先在定稿里找到、用题干核对再改。说不清楚的条目去 `本地化/报告/通读/结果-<册>.md` 看原报告。

清单二.2（编辑校对记录漏进正文）：在你那几册里搜「题库」「原题」「应为」，改成学生能读懂的说法（如「答案应为 be，作定语」），不出现「题库」；没意义的删。

同步定稿删题后按模板重编 `no`、改 `numbered_total`。

## 三、收尾

1. `python3 -I 本地化/脚本/定稿校验.py`：你那几册的条目必须为零。
2. 结果写到 `本地化/报告/通读/修改结果-<组名>.md`：一个表，每行一处：册、位置、清单条目号（如 二.1 / 三·答案错）、改法（改前 → 改后，摘要即可）。误报也列，改法写「误报：理由」。表后写「改 N 处，误报 M 处」。
